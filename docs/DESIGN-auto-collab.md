# 設計：有邊界的自動協作（Claude → G8毛 → Codex）

> 狀態：設計稿，待 Ryan 確認後實作。本文件自足。
> 這項功能會改變本程式原本「所有交接都由人手動觸發」的設計原則，所以先寫清楚邊界再動手。

## §1 目標

Ryan 給一個任務之後，三個角色自己來回把它做完，不需要每一步都按「轉交」：

| 角色 | 在自動流程中的職責 | 能不能碰專案檔案 |
| --- | --- | --- |
| Claude | 規劃、最終審查 | 只讀（提示中明確要求不修改） |
| G8毛 | **傳輸**：把上一位的產出整理成給下一位的交接訊息；**自己審查一次**：先給出通過或退回的判定 | 不能，它只看得到文字 |
| Codex | 實作 | 可以 |

Local LLM 不在第一版的自動流程裡。

## §2 流程

```
使用者輸入任務
   │
   ▼
[A] Claude 規劃 ──────────────► 計畫 P
   │
   ▼
[B] G8毛 審查計畫並轉寫成實作交接單
   │   判定 REVISE ──► 把意見送回 [A]（算一回合）
   │   判定 PASS
   ▼
[C] Codex 依交接單實作 ───────► 實作回報 R
   │
   ▼
[D] G8毛 審查回報（附 git 變更摘要），轉寫成審查請求
   │
   ▼
[E] Claude 最終審查（可讀專案）
       判定 APPROVED ──────────► 結束
       判定 CHANGES_REQUESTED ─► 意見經 [B] 送回 Codex（算一回合）
```

每則送出的訊息都用固定的信封格式，要求對方的回覆**第一行**必須是 `VERDICT: <值>`。
讀不到合法判定時，流程暫停並請使用者決定，不猜測。

## §3 邊界（全部都是硬性的）

1. **只在使用者按下「開始」後執行**，一次只跑一個任務。程式啟動時永遠不會自動開始，設定也不會記住「自動模式開啟」。
2. **回合上限**：預設 3，可設 1–10。到上限就停下來並回報目前狀態。
3. **每一步的等待上限**：Claude／Codex 預設 15 分鐘，G8毛 預設 5 分鐘。逾時即暫停。
4. **工具核准永遠不自動**。任一角色出現核准請求時流程暫停，等使用者在面板上核准或拒絕後才繼續。
5. **任何錯誤即暫停**：連線中斷、後端回錯誤、訊息被安全過濾攔下，都不重試超過一次。
6. **隨時可停**：執行期間畫面上固定有「停止」按鈕，按下後不再送出任何新訊息，並對正在回覆的角色送出取消（G8毛 不支援取消，只能等它回完）。
7. **不切換專案或任務**：執行期間鎖住專案／任務切換，避免訊息送進錯的對話。
8. **全程留紀錄**：每一步寫入既有的 handoffs 與 events，時間線看得到完整經過，可匯出。

## §4 G8毛 的特殊處理

G8毛 是非官方整合，現在的設計是「每個動作都要人按一次同意」、而且明文寫著不輪詢、不轉送。自動流程必須放寬這兩點：

- **一次性的執行授權**：開始時跳出一個對話框，完整顯示既有的揭露文字，並寫明這次執行最多會對 G8毛 送出幾則訊息、多久讀取一次回覆。使用者同意後，只在這一次執行期間有效，執行結束或停止時立即失效。
- **輪詢讀取回覆**：送出後每 5 秒讀一次，直到出現新的 G8毛 回覆或逾時。這次執行對 G8毛 的總請求數有上限（預設 200），到上限即暫停。
- 手動操作的單次同意機制保持原樣，不受影響。

**帳號風險**（需要 Ryan 明確接受）：這條路是用你的 ChatGPT 登入憑證呼叫非公開介面。手動偶爾用和程式自動連續呼叫，在對方眼中是不同的行為，有被限流或帳號受限的可能。我無法評估機率，也無法替你降低到零。

## §5 已知限制

- **G8毛 看不到程式碼**。它的審查只能根據文字回報和 git 變更摘要，抓得到「計畫不合理」「回報與要求不符」，抓不到程式裡的 bug。真正讀程式碼的審查是 Claude 在 [E] 做的。
- **Claude 和 Codex 共用同一個資料夾**。流程靠提示要求 Claude 不改檔來避免互相覆蓋，這是約定而不是強制。要強制需要另外做 worktree 隔離，不在這一版。
- **費用**：每一回合至少是 Claude 兩次、Codex 一次、G8毛 兩次請求。回合上限是唯一的費用控制。
- **判定靠文字約定**。模型偶爾會不照格式回，那時流程會暫停請你決定。

## §7 驗收（離線、用替身 adapter）

1. 正常路徑：A→B→C→D→E 一輪通過，五則訊息依序送給正確的角色，內容含上一步的回覆。
2. [B] 判定 REVISE：訊息回到 Claude，不送 Codex。
3. [E] 判定 CHANGES_REQUESTED：經 G8毛 回到 Codex；達回合上限時停止，之後不再有任何送出。
4. 回覆缺少合法判定：暫停，不送下一步。
5. 執行中出現核准請求：暫停；核准後繼續；全程沒有任何自動核准的呼叫。
6. 按停止：之後零送出；對 Claude／Codex 有送取消。
7. 任一步逾時、任一 adapter 丟錯：暫停並顯示原因。
8. G8毛 授權：未授權時自動送出被拒；授權期間可送與讀；執行結束後再呼叫被拒；請求數到上限即暫停。
9. 程式啟動與一般輪詢期間，沒有任何 adapter 被呼叫（既有測試維持通過）。
10. 既有測試基準不退步；提到「自動協作關閉」文字的既有斷言若需調整，逐條列出。

真實後端的驗收另外做：先用一個只需回覆文字的小任務跑一輪，確認三方真的接得起來，再試會改檔的任務。
